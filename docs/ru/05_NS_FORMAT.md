# Формат проекта NS

Один именованный проект = одна БД SQLite или защищенная паролем SQLCipher с расширением .ns, не JSON, Markdown или ZIP. Сигнатура обычной БД: SQLite format 3 с завершающим NUL. Для обеих user_version=1, journal_mode=DELETE, synchronous=FULL и эксклюзивная блокировка при открытии.

```sql
CREATE TABLE project_meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE notes (id TEXT PRIMARY KEY, title TEXT NOT NULL, html TEXT NOT NULL,
  sort_order INTEGER NOT NULL, updated_at INTEGER NOT NULL);
CREATE INDEX notes_order_idx ON notes(sort_order);
PRAGMA user_version=1;
```

Метаданные: format = nocturne-notes-v1; created_at = Unix-миллисекунды строкой; active_note = UUID. Принимается только текущий маркер nocturne-notes-v1. Заметки: UUID, заголовок до 250 символов, HTML до 5 000 000 символов, целый sort_order и updated_at в Unix-миллисекундах. Чужая SQLite или пустой/поврежденный проект отклоняются до изменения.

Дополнительная note_trash(id,title,html,sort_order,updated_at,deleted_at) создается лениво в транзакции. Корзина/восстановление сохраняют UUID и HTML; восстановление возвращает позицию в пределах текущего списка. Окончательное удаление необратимо. Использовать резервные копии. Сортировка и дублирование транзакционные. ProjectStore — единственный писатель. «Сохранить как» проверяет логическую копию перед переключением. Перед резервным копированием или переносом закрыть приложение; при записи возможны журнальные/recovery-файлы. Undo только в сессии. Не менять схему и маркер без явного согласования и плана защиты данных.

## Защита паролем
Незащищенный .ns сохраняет SQLite и схему версии 1. Защищенный .ns — SQLCipher 4.20.0 с зашифрованными заголовком, страницами и recovery; обычная SQLite его не откроет. Пароль не хранится в настройках. Смена/снятие пароля и «Сохранить как» создают проверенную логическую копию до замены; делайте резервные копии. Recovery защищенного проекта внутри БД, не в открытом sidecar. Обычный recovery атомарно записывается с flush; оставшиеся временные recovery-файлы этого проекта удаляются перед защитой. Защита не скрывает имя файла, не стирает прежние открытые копии и не шифрует экспорт. Не редактируйте один проект одновременно.

### Журнал отката
`.ns-journal` — журнал отката SQLite. Режим DELETE, синхронная запись FULL и эксклюзивная блокировка не меняются; журнал может оставаться рядом с открытым проектом до закрытия. Не удаляйте и не переносите его отдельно при открытом проекте или после сбоя. SQLCipher шифрует содержимое страниц отката защищенной базы; заголовки и структурные метаданные журнала не обязательно зашифрованы. Расширенный тест создает реальный hot journal, ищет синтетические открытые маркеры в журнале и БД, прерывает записывающий процесс, проверяет откат, корзину и зашифрованный recovery, а также штатную очистку. Обычные проекты и прежние копии не зашифрованы. Установка защиты не обеспечивает безопасное стирание удаленных блоков, старых резервных копий, снимков диска или системного файла подкачки. Новый минимум — восемь кодовых точек Unicode; рекомендован длинный уникальный пароль.

### Метаданные закрепления и временные файлы
Необязательное `project_meta.pinned_notes` — JSON-массив UUID заметок; отсутствие означает нет закрепленных. Без новых таблиц/столбцов, версии схемы и маркера. Копии сохраняют все метаданные, включая шифрование/смену/снятие пароля. Управляемые черновики — прямые приватные `draft-<UUID>.ns` и соответствующие SQLite/временные sidecar; activeDraft в настройках указывает на прерванный сеанс, без пароля/текста. При запуске и подтвержденном выходе очищаются только управляемые прямые обычные файлы, не пользовательские именованные файлы и не ссылки на каталоги. Текущий прерванный файл и recovery сохраняются до успешного сохранения/отказа. Удаление не равно безопасному стиранию.

ID закрепленных остаются в прежнем массиве метаданных; фактический порядок в прежнем sort_order. При открытии сохраненный порядок стабильно разбивается на закрепленные и обычные одной транзакцией только при необходимости. ID, время, заголовки, HTML, активный ID и корзина не меняются. Новые закрепленные добавляются в конец префикса, открепленные на границу; дублирование и восстановление не могут попасть в префикс. Версия схемы и шифрование прежние.


### Идентичность восстановления
Обычный recovery — атомарный JSON-файл в каталоге recovery конкретной редакции, имя — SHA-256 точных BigInt device, inode и birthtimeNs. При inode=0 допустим native realpath и birthtimeNs только для обычного файла с одной жесткой ссылкой; неоднозначность вызывает отказ. При доступном идентификаторе псевдонимы одного файла используют общий recovery, копии и замены изолированы. Перед записью идентичность проверяется заново. Замена именованного проекта с несколькими жесткими ссылками при защите или перезаписи запрещена. Защищенный recovery хранится в необязательной таблице `protected_recovery(id,title,html,updated_at)` внутри зашифрованной БД. Совместное восстановление между редакциями и восстановление внешне удаленного/замененного проекта не гарантируется.
